# data-grid-service-java

支撑可编辑数据表格的服务端能力：服务端统一查询与写入，保证并发翻页、
排序、筛选、批量修改下的结果稳定可信，失败时给出可区分、可解释的原因。

## 运行与测试

```bash
mvn test          # 运行全部自动化测试
mvn spring-boot:run
```

## 一致性语义

### 快照隔离（MVCC）

- 存储层每次提交（单行写入或一次批量）都会发布一个**不可变快照**，并带单调
  递增的提交版本号（commit version）。
- 任何一次读取都作用于某一个已提交的完整快照：不会读到字段级或行级的混合
  状态，也不会读到未提交的中间结果。
- 读不阻塞写：读只访问已发布的不可变快照，写只在提交瞬间切换头指针；慢查询
  持有旧快照即可，写入照常进行。

### 排序与筛选的确定性

- 多列排序的优先级即请求中排序列表的顺序（靠前优先）。
- 并列时一律按行 id 升序裁决，因此任意查询构成**全序**：同一查询在任意翻页
  顺序、任意并发度下返回的顺序与内容完全一致。
- 类型不可比较的值（如字符串与数字混排）会报 `TYPE_MISMATCH`，绝不产生任意
  顺序。

### 游标翻页与持续写入共存

- `POST /grid/query` 返回第一页和一个不透明游标；后续页用
  `POST /grid/query/page` 传入游标。
- 游标在创建时**钉住（pin）当时的快照**，整段翻页都以该自洽快照为基准：
  翻页过程中其他来源的新增/删除不会造成重复行或缺行（新数据对本次翻页不
  可见，已删除数据仍可见）。
- 游标失效原因可区分：
  - `CURSOR_INVALID`（400）：游标格式非法；
  - `CURSOR_EXPIRED`（410）：游标空闲超时，或其快照已超出保留窗口被驱逐。
- 另提供无状态偏移翻页 `POST /grid/query/offset`，每次读最新快照，不返回
  游标；适合不要求跨页一致的场景。

### 乐观并发控制

- 每行携带 `version`，每次写入后递增。
- 写入必须携带 `expectedVersion`；与已提交版本不一致即拒绝，原因
  `VERSION_CONFLICT`（批量结果中逐行标注，HTTP 层单行场景映射为 409）。
- 并发编辑同一行时恰好一个成功，其余收到版本冲突，**不会静默覆盖**。

### 批量编辑

- `atomic=true`：整批全部生效或全部不生效。任一行校验失败（行不存在
  `ROW_NOT_FOUND`、版本冲突 `VERSION_CONFLICT`、类型错误 `TYPE_MISMATCH`、
  未知列 `UNKNOWN_COLUMN`）时整批不提交，成功行标记 `BATCH_NOT_COMMITTED`，
  不会留下部分写入。
- `atomic=false`：逐行独立处理，返回每一行可分辨的结果（成功含新版本号，
  失败含机器可读 reason 与人类可读 message）。

### 具名保存视图

- 视图保存筛选、排序、分页大小与列展示配置（`PUT /grid/views/{name}`，
  `GET /grid/views/{name}`）。
- 字段定义增删或改类型后旧视图仍能打开：失效部分（列已删除、筛选值与列
  新类型不匹配、页大小超上限）被降级剔除，并在响应的 `degradations` 中逐条
  说明，可用部分原样保留。

## 错误模型

所有领域错误携带机器可读 reason 与可解释 message：

| reason | HTTP | 含义 |
| --- | --- | --- |
| `ROW_NOT_FOUND` | 404 | 目标行不存在 |
| `VERSION_CONFLICT` | 409 | 基于过期版本的写入被拒绝 |
| `BATCH_NOT_COMMITTED` | 409 | 整批因其他行失败而未提交 |
| `CURSOR_INVALID` | 400 | 游标格式非法 |
| `CURSOR_EXPIRED` | 410 | 游标超时或快照已被驱逐 |
| `UNKNOWN_COLUMN` | 400 | 筛选/排序/写入引用了不存在的列 |
| `TYPE_MISMATCH` | 400 | 值与列类型不匹配或不可比较 |
| `VALIDATION_FAILED` | 400 | 请求参数非法（如页大小非正） |
| `VIEW_NOT_FOUND` | 404 | 视图不存在 |

## API 一览

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/grid/query` | 第一页（筛选+排序+页大小），返回游标 |
| POST | `/grid/query/page` | 游标取下一页 |
| POST | `/grid/query/offset` | 无状态偏移翻页 |
| POST | `/grid/edit` | 批量编辑（`atomic` 切换整批/逐行语义） |
| POST | `/grid/rows` | 新增行 |
| DELETE | `/grid/rows/{id}` | 删除行 |
| GET/PUT | `/grid/schema` | 查看/更新列定义 |
| PUT/GET | `/grid/views/{name}` | 保存/加载具名视图（加载时自动降级） |

## 可配置项（`application.properties`，前缀 `grid.`）

| 配置 | 默认值 | 说明 |
| --- | --- | --- |
| `grid.max-page-size` | 200 | 客户端可请求的最大页大小（超出会被截断） |
| `grid.default-page-size` | 50 | 未指定页大小时的默认值 |
| `grid.retained-snapshots` | 64 | 为游标翻页保留的最近提交版本数；被钉住的快照不会被驱逐 |
| `grid.cursor-ttl-millis` | 300000 | 游标自上次使用起的有效毫秒数，超时报 `CURSOR_EXPIRED` |

## 测试覆盖

`GridServiceTest` 与 `GridApiTest` 覆盖：

- 并发翻页：8 线程并发翻同一查询，结果逐行一致；多列排序优先级与行 id 裁决；
- 游标与写入共存：翻页中插入/删除，结果与钉住快照完全一致，无重复无缺失；
  游标过期/非法原因可区分；
- 乐观锁：过期版本写入被拒且原值不被覆盖；16 线程并发改同一行恰好一个成功；
- 批量：原子批一处失败整批不落盘；逐行批好行生效、坏行给出各自原因；
- 视图兼容：删列/改类型后旧视图可打开，降级项逐条说明；
- 并发读写：写线程持续原子提交两行，读线程 2000 次采样从未观察到跨行混合
  版本；游标与偏移翻页结果一致。
